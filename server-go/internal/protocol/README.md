# Legacy protocol layer

This package is a byte-compatible port of the client/server framing layer from mir2x.

Primary C++ references:

- `common/src/clientmsg.hpp`
- `common/src/servermsg.hpp`
- `common/src/msgf.hpp`
- `server/src/netdriver.cpp`
- `server/src/channel.cpp`
- `common/src/zcompf.cpp`
- `common/src/cerealf.hpp`
- `common/src/serdesmsg.hpp`

## Frame format

Every message starts with one head byte. Bit 7 means that a response ID follows.

```text
head byte = code | response_bit
[varint response_id]  only when response_bit is set
body                  depends on message kind
```

Message kinds:

| Kind | Body |
|---|---|
| 0 empty | no bytes |
| 1 fixed compressed | `varint(compressed_size)` + XOR mask + compressed bytes |
| 2 fixed raw | exactly `data_len` bytes |
| 3 variable | `varint(payload_size)` + payload |

All integer lengths are little-endian base-128 varints.

XOR compression keeps a bit mask and appends only non-zero bytes. Messages with `data_len >= 256` use the wide 64-bit mask variant from `zcompf::xorEncode64`.

## Fixed payloads

`client_payloads.go` and `server_payloads.go` contain the packed fixed-size payload structs. `wire.go` provides declaration-order encoding without Go alignment padding.

`CMChatMessageHeader`, `CMRequestLatestChatMessage`, `SMOnlineOK` and `SMCORecord` have explicit codecs because their bitfield/union layout cannot be represented by ordinary Go struct alignment.

All fixed message payloads are tested against the C++ `sizeof` table.

## Cereal PortableBinary and serialized messages

`portable_binary.go` implements the layout emitted by `cereal::PortableBinaryOutputArchive`:

- leading endian byte;
- explicit-width little-endian integers;
- one-byte bool;
- uint64 size tags;
- length-prefixed strings and byte vectors.

`cereal.go` implements the `cerealf` envelope used by variable messages:

- `CF_NONE` raw archive;
- `CF_XOR` sparse XOR compression;
- `CF_ZSTD` Zstandard compression.

The five `serdesmsg.hpp`/Lua batches are implemented in `serdes_basic.go`, `serdes_second_batch.go`, `serdes_item_batch.go`, `serdes_team_runtime_batch.go`, `lua_var.go` and `serdes_lua_batch.go`. They cover 100 golden fixtures generated from a standalone C++ cereal probe and checked into `testdata/serdes-golden.json`; all 94 declared `serdesmsg.hpp` types are directly covered.

Current coverage includes player/guild/ranking DTOs, ground items/firewalls/safe zones, chat messages, NPC events, magic keys, peer configuration, core `SDItem`, inventory/equipment, direct trade, auction, stall, item storage, runtime config, health/buffs, team messages and the recursive Lua variant.

Known ordering nuance: C++ `std::unordered_map` iteration order is implementation-defined. The Go encoder writes those maps in ascending key order, which is semantically compatible with cereal decoding but does not guarantee byte-for-byte equality for multi-entry unordered maps.

## ABI-sensitive findings

The reference MinGW x64 build uses the MS bitfield ABI. Observed and tested facts:

- `sizeof(ActionNode) == 28`;
- `ActionNode` packs the first three fields into a 4-byte flag word;
- `sizeof(StaticBuffer<64>) == 68`;
- `sizeof(StaticBuffer<128>) == 132`;
- `sizeof(SMChatMessageHeader) == 16`, with both bitfields in the second 8-byte storage unit;
- `sizeof(CMRequestLatestChatMessage) == 1036`;
- `SMOnlineOK` and `SMCORecord` player bitfield positions are captured in the layout fixture tests.

Do not replace these wire structures with `encoding/gob`, JSON, or Go's naturally aligned structs.
