## 一、原则（先立规，再动手）

| 编号 | 原则 | 含义 |
|---|---|---|
| P1 | **除渲染外全复刻** | 只有“画到屏幕上”换成 Godot；游戏逻辑、状态机、判定、数据流全照原实现 |
| P2 | **渲染之外不重构** | 不“顺手优化”、不“我觉得这样更好”。原实现怎么判就怎么判 |
| P3 | **先读后写** | 每个系统动手前必须读完对应 C++ 源文件，写不清依据就不写代码 |
| P4 | **边角规则单独成文** | 掉落归属、PK 红名、怪物仇恨、命中判定，先写规则文档再实现 |
| P5 | **每个系统可独立验收** | 验收标准写成可执行检查项，不靠“看起来对” |

### 2.4 Lua 脚本归属（已查证，客户端不需要 Lua 运行时）

**结论：690 个 Lua 脚本 / 48,462 行，一行都不用转 GDScript。**

| 证据 | 位置 | 说明 |
|---|---|---|
| 客户端 Lua 模块只有 **17 行** | `client/src/clientluamodule.cpp` | 仅 1 个 `addLogString` |
| 客户端只导出 **1 个** API | `processrun.cpp:1416` `bindFunction("addCBLog")` | 仅用于日志 |
| `luaCommand()` 是 GM 调试控制台 | `processrun.cpp:1136` | 非游戏脚本执行入口 |
| 服务端导出 **20+ API** | `servermap.cpp:88-546` `npchar.cpp:60-334` | `addGuard` / `addMonster` / `isSafeGrid` / `dbSetGKey` 等 |
| 脚本目录 | `server/script/` | map 285、npc 341、quest 44，**全部服务端执行** |

**客户端如何获得 Lua 逻辑的结果**：不执行脚本，只消费服务端下发的消息。

| Lua 语句 | 服务端下发 | 客户端行为 |
|---|---|---|
| `addSafeZone({x,y,r})` | `SM_SAFEZONELIST` | 画安全区高亮 |
| `addGuard('禁军卫士', x, y, dir)` | `SM_CORECORD` | 显示 NPC |
| `addMonster(...)` | `SM_CORECORD` | 显示怪物 |
| `setNPCSell{...}` | `SM_NPCSELL` | 显示商品列表 |
| NPC 对话 XML | `SM_NPCXMLLAYOUT` | 解析排版（S11） |
| 任务状态 | `SM_QUESTDESPUPDATE` / `SM_QUESTDESPLIST` | 任务面板 UI |

**mock 侧决策**：`tools/mock-server/` **不嵌 Lua**，按协议下发固定数据即可。
想验证真实刷怪逻辑，属于将来真做服务端的事，不混入本轮。

**唯一可选的 Lua 需求**：客户端 GM 调试控制台（原版 `luaCommand` 功能）。
本轮**不做**。

## 五、系统分解与验收

14 个可独立验收的系统。**每个都先读完原实现再动手**。

### S1 协议层
- **原实现**：`clientmsg.hpp`(20.6KB) `servermsg.hpp`(20.2KB) `msgf.hpp` `zcompf.cpp` `cerealf.hpp`
- **要做**：87 CM + 115 SM；4 种消息体；LEB128；XOR（含 64 位宽）；cerealf 三种标记
- **验收**：① 编码→解码字段一致 ② 原 C++ 字节流回放逐字段比对 ③ 尺寸与 `tools/struct_sizeof.txt` 一致
- **状态**：编解码器已写，**回放未验证**

### S2 数据表
- **原实现**：`common/src/*.inc`：`itemrecord.inc`(262KB) `monsterrecord.inc`(142KB) `maprecord.inc`(225KB) `magicrecord.inc`(61KB)
- **要做**：C++ 静态表 → Godot 可读数据（JSON/二进制），提供查询 API
- **验收**：条目数一致；随机抽 100 条逐字段比对
- **注**：纯数据转换，可脚本自动生成

### S3 地图渲染
- **原实现**：`mir2map.hpp` `mir2xmapdata.hpp` `client/src/clientmap.cpp`
- **要做**：.bin 解析（已完成）、瓦片层、**物件层 obj[0]/obj[1]**、光照、动画瓦片、深度排序
- **验收**：与原件对比截图；物件层正确；动画瓦片按 `tickType/frameCount` 播放
- **状态**：瓦片层完成，**物件层/光照/动画未做**

### S4 动作状态机 ⭐核心
- **原实现**：`actionnode.hpp` `motion.hpp` + `client/src/hero.cpp`(1733 行)
- **要做**：46 种 MotionType 的帧数、速度、方向、混合；15 种 ActionType 转换；`gfxID` 编码
- **验收**：每种动作播放正确，帧数与原版一致（逐帧截图比对）
- **风险**：**最复杂的单体系统**，`hero.cpp` 1733 行几乎全是动作逻辑

### S5 移动与寻路
- **原实现**：`pathf.cpp`(18KB) `clientpathfinder.hpp`
- **要做**：8 方向判定、逐格移动、A\*、`PathFindType`（障碍/占用/锁定/自由）
- **验收**：同起终点路径与原版一致；不可走格正确拒绝
- **状态**：**未开始**（当前点击是瞬移）

### S6 主角
- **原实现**：`myhero.cpp` `hero.cpp`
- **要做**：动作队列、本地预测、上报服务端、装备外观分层合成（发型/头盔/衣服/武器/影子）
- **验收**：穿戴变化实时反映；动作衔接无跳帧
- **注**：外观是**多层叠加**，见 `pngtexoffdb.hpp:humanKey` 位编码

### S7 其他角色
- **原实现**：`clientmonster.cpp`(892 行) `clientnpc.cpp` + **40 个怪物专属类**
- **要做**：怪物/NPC/其他玩家的生成、动画、朝向、血条；40 个特殊怪物的独有行为
- **验收**：每种怪物动画正确；特殊怪物（沙鬼钻地、祖玛、触龙神等）行为一致
- **风险**：40 个类逐个读，**最易被低估的隐藏工作量**

### S8 魔法系统
- **原实现**：`basemagic.cpp` `followuidmagic.cpp` `fixedlocmagic.cpp` `attachmagic.cpp` `magicdb.cpp`
- **要做**：三类魔法的飞行、命中、特效；`magicrecord.inc` 61KB 数据
- **验收**：火球、雷电、治愈等典型魔法表现正确

### S9 物品与背包
- **原实现**：`inventoryboard.cpp`(775 行) `itemlistboard.cpp` `sditem.hpp`
- **要做**：背包格、穿戴槽、腰带 6 格、地面物品、耐久、品质染色、拾取
- **验收**：移动/装备/丢弃/拾取全通；`seqID` 去重正确

### S10 界面系统 ⭐工作量大
- **原实现**：**28 个 board** + `widget.cpp`(1194 行)
- **要做**：28 个面板的布局、交互、数据绑定
- **验收**：每个面板可打开、数据正确、可关闭
- **注**：面板多但逻辑重复，**可模板化**

### S11 XML 布局引擎
- **原实现**：`xmltypeset.cpp`(1730 行) `xmlparagraph.cpp`(590 行)
- **要做**：NPC 对话 XML 解析 + 排版（换行、对齐、颜色、图片混排）
- **验收**：同一 XML 渲染结果与原版一致

### S12 聊天

- **要做**：频道切换、私聊、喊话、行会、系统消息、表情、历史查询
- **验收**：各频道收发正确；表情显示正确

### S13 小地图与特效
- **原实现**：`minimapboard.cpp`(608 行) `motioneffect.cpp`
- **要做**：小地图缩略渲染、点位；受击闪烁、光环、HP 条
- **验收**：小地图位置与主视图一致

### S14 音效
