### 关键技术结论（已验证，勿重新推导）

1. **地图 .bin 格式**
   - 压缩标记在**文件末尾**（非开头），1=zstd
   - 解压后第 0 字节是 cereal PortableBinary **端序标记**（1=小端），所有 cerealf 消息都有这 1 字节
   - 结构：`[endian:u8][w:u64][h:u64][count:u64][count × BLOCK]`
   - BLOCK=260B = TILE(8) + 4×CELL(63)
   - CELL=63 = LAND(3) + LIGHT(4) + 2×OBJECT(28)
   - **曾把 CELL 当 58 字节，导致瓦片有效率仅 26.8% 且棋盘错位**

2. **瓦片尺寸**
   - 素材 96×64，BLOCK = 2格×48×32 = 96×64，因此 tile_scale=1.0
   - **曾误设 0.5 导致稀疏棋盘**

3. **协议**
   - 87 CM + 115 SM，全部抽取无缺失
   - 帧格式：`[headCode][respID:LEB128][bodySize:LEB128][mask][body]`
   - headCode 0x80 位 = hasResp
   - 结构体尺寸用 C++ 实测（`tools/struct_sizeof.txt`），非手算

   Godot 直接退出码 1、零输出。必须 `if DisplayServer.get_name() == "headless": return`

   进程静默退出，不是报错。排查时先 `--script` 单独 load 该脚本看编译错误

### 三个关键修正（都是"想当然"导致的）

1. **选人图库 gender 位写反了**
   `key = anim<<3 | layer<<9 | shadow<<10 | gender<<11 | job<<12`，
   bit11 是 **1=男 0=女**。初版按 0=男 实现，导致帧表与实载整体互换。
   发现方式：遍历 30 组「帧表帧数 vs 实载帧数」，全部对不上，
   且 male/female 结果正好互换 —— 才反应过来是位语义反了。
   校准锚点：战士男 anim1=20 帧 vs 女=11 帧（差异最大的一组）。

2. **调色板 PNG 缺 PLTE**
   选人图库 74 张里有 31 张是 colorType 3（调色板），且**全在 shadow 层**。
   APNG 拆帧重建时只搬 IHDR+IDAT，解码器报
   `IDAT: Missing PLTE before IDAT` 并整帧失败。
   PNG 规范 11.2.3 要求 PLTE 在 IDAT 之前，必须补上（tRNS 可选）。

3. **CM 消息编码用错了**
   CM_LOGIN 在 sm_table 里是 type 1（掩码压缩体），不是 type 2（裸 body）。
   直接发裸 body 服务端收不到，表现为"发包成功但无应答"。
   必须走 `net.send()` 让它按表选路。
