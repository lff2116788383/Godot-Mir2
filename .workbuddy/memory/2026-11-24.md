### 关键技术结论（已验证，勿重新推导）

1. **地图 .bin 格式**
   - 压缩标记在**文件末尾**（非开头），1=zstd
   - 解压后第 0 字节是 cereal PortableBinary **端序标记**（1=小端），所有 cerealf 消息都有这 1 字节
   - 结构：`[endian:u8][w:u64][h:u64][count:u64][count × BLOCK]`
   - BLOCK=260B = TILE(8) + 4×CELL(63)
   - CELL=63 = LAND(3) + LIGHT(4) + 2×OBJECT(28)
   - **曾把 CELL 当 58 字节，导致瓦片有效率仅 26.8% 且棋盘错位**

2. **瓦片尺寸**
   - 素材 96×64，BLOCK = 2格×48×32 = 96×64，因此 tile_scale=1.0
   - **曾误设 0.5 导致稀疏棋盘**

3. **协议**
   - 87 CM + 115 SM，全部抽取无缺失
   - 帧格式：`[headCode][respID:LEB128][bodySize:LEB128][mask][body]`
   - headCode 0x80 位 = hasResp
   - 结构体尺寸用 C++ 实测（`tools/struct_sizeof.txt`），非手算

`texture/proguse/` 就是 UI 图库，1509 张 PNG，文件名 = 8 位 hex texID。
此前多轮对话中「素材包缺 UI 图库（0x07xxxxxx 段）」的结论是**错的**。

06000000=328x466 与 myherostateboard 面板尺寸吻合。
新增 `scripts/data/proguse_tex.gd` 作为图库加载器，面板已按真贴图还原。

### 头像贴图 id 规则
`0x02000000 + jobGfxIndex*2 + (gender ? 0 : 1)`（hero.hpp:324 faceGfxID）
实测 proguse 里 02000000..02000005 共 6 张 84x94 = 3 职业 × 2 性别。
`0x010007CF` 是问号占位图（84x94），不要误当头像。

### 音频系统
- 848 音效（seff/*.WAV）+ 25 BGM（bgm/*.mp3）
- 四段 ID：0x00 UI(12) / 0x01 人形(82) / 0x02 怪物(647) / 0x04 魔法(107)
- 怪物：`0x02000000 + lookID*16 + offset`，表里无 seff 覆盖配置，全走默认
- 魔法：`0x04000000 + seffBase*16 + stageIndex`，seffBase 已从 .inc 回填 53 条
- 3D 定位：distance 用**欧氏距离**，angle = 90 - 180*atan2(-dGY,dGX)/π，
  clamp 255 后映射成 `(sin*scaled, 0, -cos*scaled)`

### 三个新踩的坑
1. **headless + AudioStreamPlayer 会静默崩溃**：无音频驱动时创 128 个播放器，
   Godot 直接退出码 1、零输出。必须 `if DisplayServer.get_name() == "headless": return`
2. **中段背景要先铺不透明黑底**：原版 cbmiddle.cpp 的 m_bg 就是 fillRectangle(A_SHF(0xFF))，
   否则背景图半透会透出地图
3. **解析错误会让场景测试完全无输出**：`--run-test` 下脚本 Parse Error 表现为
   进程静默退出，不是报错。排查时先 `--script` 单独 load 该脚本看编译错误
