### 关键技术结论（已验证，勿重新推导）

1. **地图 .bin 格式**
   - 压缩标记在**文件末尾**（非开头），1=zstd
   - 解压后第 0 字节是 cereal PortableBinary **端序标记**（1=小端），所有 cerealf 消息都有这 1 字节
   - 结构：`[endian:u8][w:u64][h:u64][count:u64][count × BLOCK]`
   - BLOCK=260B = TILE(8) + 4×CELL(63)
   - CELL=63 = LAND(3) + LIGHT(4) + 2×OBJECT(28)
   - **曾把 CELL 当 58 字节，导致瓦片有效率仅 26.8% 且棋盘错位**

2. **瓦片尺寸**
   - 素材 96×64，BLOCK = 2格×48×32 = 96×64，因此 tile_scale=1.0
   - **曾误设 0.5 导致稀疏棋盘**

3. **协议**
   - 87 CM + 115 SM，全部抽取无缺失
   - 帧格式：`[headCode][respID:LEB128][bodySize:LEB128][mask][body]`
   - headCode 0x80 位 = hasResp
   - 结构体尺寸用 C++ 实测（`tools/struct_sizeof.txt`），非手算
